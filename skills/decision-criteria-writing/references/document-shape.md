# 판단 기준 문서 골격

이 골격은 새 문서의 시작점이다. 판단에 필요하지 않은 선택 항목은 제거한다.

```markdown
# {판단 주제}

- 상태: `{draft|adopted|validated|revised}`
- 검토일: {YYYY-MM-DD, 필요한 경우}
- 주제: {핵심 개념}
- 선택: {한 줄 기본값, 필요한 경우}

## 결론

**채택: {기본 선택과 적용 조건}.** {핵심 근거와 감수할 비용}.

**거부: {흔한 오판 또는 선택하지 않을 조건}.** {이유}.

**보류: {측정·요구사항 확인 전 확정하지 않을 내용}.** {확인할 항목}.

## 빠른 기준

| 질문 | 판단 |
| --- | --- |
| {가장 강한 제외 조건인가?} | {기본값 유지 또는 거부} |
| {대안이 필요해지는 조건인가?} | {대안 우선 검토} |
| {운영 비용을 감당할 수 있는가?} | {불가능하면 보류} |

## 적용 범위

{현재 문서가 결정하는 것과 결정하지 않는 것을 구분한다. 인접 기준은 링크한다.}

## 1. 판단 순서 또는 기본 선택

{선택지를 비교하기 전에 확인할 전제와 가장 단순한 기본값을 설명한다.}

## 2. 대안별 채택 조건

{각 대안의 채택 조건, 얻는 것, 비용과 예외를 설명한다.}

## 트레이드오프

| 선택 | 얻는 것 | 부담하는 것 | 선택 조건 |
| --- | --- | --- | --- |
| {기본값} | {...} | {...} | {...} |
| {대안} | {...} | {...} | {...} |

## 검증 방법

- {결론을 지탱하는 기술적 전제를 확인하는 명세·실험·측정}
- {실패·예외·변경 상황 검증}

## 관련 판단 기준

- [{인접 기준}]({상대 경로})

## 최종 판단 기준

> {기본값}. {대안으로 전환할 조건}. {거부 또는 핵심 제약}.
```

## 구성 선택 기준

| 섹션 | 추가 조건 |
| --- | --- |
| 적용 범위·비범위 | 인접한 판단과 혼동할 가능성이 있을 때 |
| 개념 비교표 | 비슷한 이름이지만 상태·책임·실패 방식이 다를 때 |
| 트레이드오프 표 | 세 개 이상의 대안이나 반복 비교 축이 있을 때 |
| 판단 순서 | 여러 질문의 순서가 결론에 영향을 줄 때 |
| 구현 예시 | 추상 기준이 코드에서 어떻게 보이는지 설명할 때 |
| 기술 문서 | 동작 전제를 확인한 공식 명세를 남길 때 |
| 관련 판단 기준 | 결정 수준을 분리했거나 중복 설명을 링크로 대체할 때 |

결론과 빠른 기준에 이미 있는 문장을 본문에서 그대로 반복하지 않는다. 본문은 결론이 성립하는 이유, 경계 사례와 비용을 보충한다.
